## Ответы на вопросы для защиты

## 1. Spring. Определение, назначение, особенности

**Spring** — фреймворк для разработки Java-приложений, предоставляющий инфраструктурную поддержку на уровне контейнера IoC. Назначение: упростить разработку за счёт внедрения зависимостей, AOP, работы с БД, web. Особенности: модульность, гибкость, интеграция с другими технологиями.

## 2. Проблемы ручной сборки приложений

- Управление зависимостями вручную (конфликты версий, транзитивные зависимости)
- Трудоёмкость компиляции
- Отсутствие воспроизводимости
- Сложность поддержки нескольких сред

## 3. Системы автоматической сборки

- **Maven** — декларативный, XML-конфигурация
- **Gradle** — гибкий DSL (Kotlin/Groovy), инкрементальная сборка

## 4. Типовая структура Java-проекта
src/main/java/ — исходный код
src/main/resources/ — ресурсы
src/test/java/ — тесты
build.gradle.kts — конфигурация сборки

## 5. Типы зависимостей в Gradle

- `implementation` — компиляция и выполнение, не экспортируется
- `api` — экспортируется транзитивно
- `testImplementation` — только для тестов
- `runtimeOnly` — только во время выполнения
- `compileOnly` — только для компиляции

## 6. Принцип инверсии управления (IoC)

**IoC** — принцип, при котором управление созданием и связыванием объектов передаётся контейнеру. Применяется для уменьшения связанности между компонентами.

## 7. IoC vs DI

**IoC** — широкий принцип (контейнер управляет объектами). 
**DI** — конкретная реализация IoC через внедрение зависимостей (конструктор, сеттер, поле).

## 8. Принципы IoC

- Инверсия управления — контейнер управляет жизненным циклом
- Внедрение зависимостей — передача зависимостей извне
- Принцип Голливуда — «не вызывай нас, мы вызовем тебя»

## 9. Сцепление и связность

- **Coupling** — степень зависимости между модулями. Желательно низкое
- **Cohesion** — степень связанности элементов внутри модуля. Желательно высокое

## 10. Принцип внедрения зависимостей

Предпочтительно внедрение через конструктор, так как:
- Обеспечивает неизменяемость полей
- Явно показывает зависимости
- Позволяет тестировать без Spring-контейнера
